## 1. 安全验收（spec 第 9 节）

### 1.2 敏感信息泄露复查

**静态审查**：`app/` 内 0 处 print/logging/控制台输出（仅文档字符串提及）；
UI 异常文案均为固定语义文本；除加密库文件外无任何磁盘写入路径。

**动态测试**（tests/phase4/test_no_secret_leakage.py，3 项）：

- 完整使用流（建库 → 保存 → 复制 → 备份 → 锁定 → 错误密码尝试 → 删除）
  后扫描全部落盘文件：无任何明文标记（密码/激活码/Token 值），
  且除 `.kdbx/.bak` 外无任何意外文件类型；
- 备份文件字节级验证保持加密且可用；
- stdout/stderr 全程无敏感值；
- UI 异常类型文案不含库内容。

### 1.3 威胁模型

`docs/THREAT_MODEL.md`：资产/信任边界图、STRIDE 七类威胁分析与对策、
设计承诺（无网络/无遥测/不 DPAPI/不自动填充）、7 项残余风险
（Python 内存擦除共性、剪贴板历史、锁屏前窗口期、主密码无后门等）

"关于"对话框、发布说明、本文档三处明示。

### 1.4 KeePassXC 兼容回归

## 2. Windows 打包（AGENTS.md 轻量规范）

### 2.1 固定构建管线（防 ad-hoc 膨胀）

- `Accnary.spec`（提交入库）：显式排除 30 个未用 Qt 模块
  （Network/Qml/Quick/Pdf/Svg/Sql/Test/…）与全部开发工具
  （pytest/pywinauto/PIL/pip/setuptools）；
- `build_exe.py`：图标转换 → 固定 spec 构建 → 体积/SHA-256 记录 →
  真机 GUI 冒烟 + `--check` 退出码验证，一条命令完成；
- 入口导入已核查：PySide6 QtCore/QtGui/QtWidgets、pykeepass 及加密依赖。

### 2.2 精简措施与结果

| 措施 | 效果 |
|---|---|
| 仅 PySide6-Essentials（Addons/WebEngine 从未引入） | — |
| 30 个 Qt 模块 + 开发工具排除 | — |
| 翻译文件仅保留 zh_CN（onefile 下随 hook 全量打包的 97 个文件在目录版已剪除；单文件版接受此约 7MB 以保单文件形态） | -6.5MB（目录版） |
| **最终产物** | **单文件 EXE 42.7 MB**（96.8MB 目录版为对照） |

> 用户选择单文件形态。代价：每次启动自解压到临时目录（启动慢几秒，
> 退出自动清理；解压内容仅程序本身，用户密码库永不经临时目录）。

### 2.3 实测验证

- 真机启动：解锁窗口正常出现（修正了 onefile 引导器子进程 + 资源管理器
  标题页误匹配两个窗口定位问题，匹配已固化为精确标题）；
- `Accnary.exe --check`：退出码 0（stack OK）；
- SHA-256：`8759f6160814b103b8793600d31df11d0ea87418e360939c013ab6198ed8a874`。
